# acknowledgements (delta)

## MODIFIED Requirements

### Requirement: Acknowledgements page in the bundle
The production bundle SHALL include a static acknowledgements page listing every third-party component distributed in `dist/`, including transitive dependencies compiled into the shipped WASM binaries. Each entry SHALL state the component name, version (or pinned commit), copyright holders, SPDX license identifier, and the full license text (identical license texts MAY be deduplicated with per-component copyright lines). The page SHALL be plain static HTML requiring no JavaScript, SHALL carry the production Content-Security-Policy like every other page, and SHALL be delivered and precached exactly like the rest of the bundle. Build-time-only tooling that is not redistributed in `dist/` (e.g., Vite, TypeScript, Playwright) SHALL NOT be required to appear.

#### Scenario: Page lists the shipped components
- **WHEN** the built acknowledgements page is viewed
- **THEN** it contains entries for at least: the typst.ts runtime and web-compiler WASM (Apache-2.0) with the Rust crates compiled into that WASM, the eform WASM module (AGPL-3.0-or-later) with the Rust crates compiled into it, the vendored armymemo package (AGPL-3.0-or-later), the Liberation Sans fonts (OFL-1.1), and the app itself (AGPL-3.0-or-later), each with copyright notice and license text

#### Scenario: Page works offline and without JavaScript
- **WHEN** the app has been visited once and the acknowledgements page is opened with the network unreachable and JavaScript disabled
- **THEN** the page renders completely from the precached bundle

#### Scenario: Page makes no external requests
- **WHEN** the acknowledgements page loads
- **THEN** no network request is made to any non-self origin, and any URLs quoted inside license texts are plain text or navigation-only links, never fetched resources

### Requirement: Inventory tracks the vendored versions
The notice inventory SHALL be generated by maintenance-time tooling from the exact versions/commits actually shipped: the pinned eform commit recorded in `vendor/eform/PROVENANCE`, the typst.ts version pinned in `package.json`, the vendored armymemo tarball, and the vendored fonts. Maintenance tooling MAY use the network; the app build SHALL NOT. An automated build-time check SHALL fail the build when the versions recorded in the inventory no longer match the versions the bundle actually ships.

#### Scenario: Dependency bump without refreshed notices fails the build
- **WHEN** the pinned typst.ts version or eform commit changes but the acknowledgements inventory still records the old version
- **THEN** `npm run build` fails, naming the stale component

#### Scenario: Build stays hermetic
- **WHEN** the app is built from a clean checkout with network access only to the npm registry
- **THEN** the acknowledgements page is produced from committed files without fetching any license data
