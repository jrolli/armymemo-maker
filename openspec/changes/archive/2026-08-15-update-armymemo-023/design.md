# Design: update-armymemo-023

## Context

The armymemo package is vendored as a versioned tarball
(`vendor/armymemo-<version>.tar.gz`) regenerated by
`scripts/vendor-armymemo.mjs` from a pinned upstream commit. Every pin must
move in one commit: the fetcher in `src/typst-service.ts`, the starter
example's `#import`, `ARMYMEMO_VERSION` in `src/armymemo-version.ts` (the
version the Markdown converter emits), the license manifest, the
acknowledgements page, README, and the typst-compilation spec —
`check-acknowledgements.mjs` fails the build on any disagreement, and
`check-markdown-conversion.mjs` compares converter output (which embeds the
`#import` line) against committed golden Typst.

Upstream f649d1b → 17b437a touches only `README.md`, `pandoc.sh`,
`pandoc.typ`, `lib.typ` (version comment), and `typst.toml` (version). The
tarball payload file list is unchanged and `vendor/eform/` is untouched. The
one clause the converter must mirror: `pandoc.typ` gained
`$if(seal)$ seal: "$seal$", $endif$` after `cf-without-encls`.

A pending proposal-only change, `add-markdown-seal-field`, proposed adding
`seal` to the converter as a documented divergence from upstream
`pandoc.typ`. Its audit of the remaining `memo()` parameters (no other gap
exists) still holds; its framing does not, since upstream now emits `seal`
itself.

## Goals / Non-Goals

**Goals:**

- Ship armymemo 0.2.3 with every version pin consistent.
- Markdown front matter accepts optional `seal`, mirroring upstream
  `pandoc.typ`'s new clause — Markdown memos can select the DOW letterhead.
- Retire the superseded `add-markdown-seal-field` change.

**Non-Goals:**

- No counterpart to upstream's `pandoc.sh` eform stamping (0.2.2): the app
  already stamps fields via the eform WASM module; `pandoc.sh` is not
  vendored or mirrored.
- No converter-side validation of the `seal` value: armymemo's own assertion
  names the accepted seals, and duplicating the list would drift on the next
  bump.
- No UI changes; the Markdown starter example keeps omitting `seal` (the
  default DOD letterhead behavior is unchanged).

## Decisions

- **D1 — Emit `seal` as an optional scalar in template clause order.**
  `memo-arguments.ts` mirrors `pandoc.typ` clause-for-clause, so `seal`
  joins `TOP_LEVEL_FIELDS` and is emitted via the existing `scalarField`
  helper after the `cf-without-encls` flag, exactly where upstream's
  `$if(seal)$` sits. Absent means not emitted (armymemo defaults to
  `"DOD"`); present means `seal: "<value>"` with the standard string
  escaping. Alternative — validating against `("DOD", "DOW")` — rejected
  per Non-Goals: the package already produces a clear assertion failure.
- **D2 — Keep the divergence list at one entry.** With upstream carrying the
  seal clause, the converter's only divergence from `pandoc.typ` remains
  "unknown fields are errors". The file-header comment stays accurate
  without edits beyond the mapping itself.
- **D3 — Refresh fixtures rather than add new ones.** The `full-metadata`
  fixture pair exists to exercise every supported field, so it gains
  `seal: DOW` and its golden Typst is regenerated. `pandoc-example.md` is
  byte-identical upstream; only its PROVENANCE pin moves to 17b437a. All
  golden `.typ` files' `#import` lines move to 0.2.3 (they embed
  `ARMYMEMO_VERSION`).
- **D4 — Remove `add-markdown-seal-field` instead of archiving it.** Archive
  is for implemented changes; this one is proposal-only and untracked in
  git. Its surviving analysis (the parameter audit) is restated in this
  change's artifacts, so nothing is lost.
- **D5 — Vendor via the script's raw-download path if the host clock
  cooperates, else `git clone` the pinned commit (design D1 of
  update-armymemo-021).** Either way the payload is the same FILES list
  tarred by the same invocation.

## Risks / Trade-offs

- [Upstream layout drift silently missing a new payload file] → The FILES
  list was diffed against upstream f649d1b…17b437a: no payload files added
  or removed; `vendor/eform/` untouched.
- [A future upstream `pandoc.typ` change to the seal clause going unnoticed]
  → Already covered by the existing bump procedure: the vendor script's
  header requires diffing `pandoc.typ` against `memo-arguments.ts` on every
  bump.
- [Unvalidated `seal` values surface as a Typst assertion rather than a
  converter error] → Accepted; the assertion message names the allowed
  values, and the converter error list stays free of a duplicated constant.

## Migration Plan

Single commit; no data or deployment migration. Rollback = revert the
commit (all pins move together).
