# Design: update-armymemo-021

## Context

The armymemo package is vendored as a versioned tarball
(`vendor/armymemo-<version>.tar.gz`) regenerated by
`scripts/vendor-armymemo.mjs` from a pinned upstream commit. The compiler's
package fetcher in `src/typst-service.ts` matches `name === "armymemo" &&
version === "<version>"` and serves the tarball; the starter example pins the
same version in its `#import`. `scripts/check-acknowledgements.mjs` enforces
that the manifest version matches the one (and only) vendored tarball, so all
pins must move in one commit. Upstream 3388e8f → f649d1b touches only
`lib.typ`, `typst.toml`, `pandoc.typ`, README, and examples — the vendored
payload file list and the `vendor/eform/` typst subtree are unchanged.

## Goals / Non-Goals

- Goals: ship armymemo 0.2.1 with every version pin (tarball, script,
  example, fetcher, manifest, acknowledgements, README, spec) consistent.
- Non-Goals: no eform/WASM changes, no manifest-schema changes, no behavior
  changes to package resolution.

## Decisions

- **D1 — Fetch the pinned commit via `git clone` this time, not the raw-file
  CDN.** The maintenance host's clock is behind raw.githubusercontent.com's
  certificate `notBefore`, so the script's `fetch()` fails with
  `CERT_NOT_YET_VALID` while `git` against github.com works. The staged
  files come from the same pinned commit either way, and the tarball is
  produced by the same `tar czf` invocation over the same FILES list, so the
  payload is identical to a script run. The script itself keeps its
  raw-download design (it works on hosts with correct clocks); only its
  COMMIT/VERSION pins change.
- **D2 — Keep the tarball versioned by filename.** `armymemo-0.2.1.tar.gz`
  replaces the 0.1.0 tarball rather than using an unversioned name:
  `check-acknowledgements.mjs` derives drift detection from the filename,
  and Vite content-hashes the asset regardless.
- **D3 — No manual footer-date edit.** The "Updated" footer date is injected
  at build time from the HEAD committer date (design D1/D2 of
  add-footer-last-updated), so committing this change updates it.

## Risks / Trade-offs

- [Upstream layout drift silently missing a new payload file] → The FILES
  list was diffed against upstream 3388e8f…f649d1b: no files were added to
  the payload set; `vendor/eform/` is byte-identical.
- [Tarball not byte-reproducible run-to-run (tar/gzip timestamps)] →
  Pre-existing property of the vendor script; the drift check keys on
  version/filename, not bytes.

## Migration Plan

Single commit; no data or deployment migration. Rollback = revert the
commit (all pins move together).
